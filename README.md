# Amazon ML Challenge 2026: Business Entity Resolution

This repository contains our high-performance, precision-optimized solution for the **Amazon ML Challenge 2026**. The goal of this challenge is to perform cross-source entity resolution (record linkage) across millions of noisy business records from 3 independent data sources without any common identifiers.

Our solution is capable of processing **26.4 million records (~2.5 GB)** in approximately **30 to 45 minutes** using an advanced hybrid pipeline consisting of Sub-word TF-IDF Blocking, Cross-Column Fuzzy Feature Extraction, and a Margin-Optimized LightGBM classifier.

---

## 🏆 Architecture Overview

Our pipeline strictly adheres to the 2-Stage Entity Resolution paradigm to overcome the $O(N^2)$ computational bottleneck.

![Architecture Pipeline](https://img.shields.io/badge/Architecture-2_Stage_Pipeline-blue)

### 1. High-Recall Candidate Generation (Blocking)
Comparing all test entities (1.7M) against all candidates (millions) is computationally impossible. We use **Fast Sparse TF-IDF Blocking** to reduce the search space.
- **Country Filtering:** We strictly isolate searches within identical countries (US, India, France), instantly eliminating >60% of unnecessary comparisons.
- **Sub-word N-grams:** We utilize Character `n-grams (3, 4)` to build TF-IDF matrices, capturing structural similarities even when words are misspelled.
- **Batched Dot-Products:** We execute highly optimized C++ sparse matrix multiplications in batches to keep RAM usage minimal.
- **Result:** Extracts the Top 30 highly probable candidates for each Source 1 entity in minutes.

### 2. Precision-Centric Feature Engineering
For every candidate pair generated by the blocker, we extract 17 highly discriminative features:
- **Fuzzy String Metrics:** Levenshtein ratios, token sort, and token set ratios via `rapidfuzz` (C++ optimized).
- **Cross-Column Matching:** Calculates diagonal similarities (e.g., matching S1 Name to S2 Address) to catch messy data where users swapped input fields.
- **Numeric Jaccard Overlap:** Extracts strict numbers (door numbers, PINs, 5-digit French postcodes) and calculates Jaccard similarity, preventing false merges of chain stores.
- **Exact Match Flags:** Binary flags that immediately signal 1.0 probability for identical strings.

### 3. Margin-Optimized LightGBM Classifier
The challenge uses a **Macro $F_{0.5}$** metric, which heavily penalizes False Positives (predicting a match when none exists). To counter this:
- **LightGBM:** Fast, tree-based gradient boosting trains on the 17 features.
- **Precision Optimizer:** A custom threshold-sweeping algorithm that strictly enforces inter-candidate margins. If a candidate's probability trails too far behind the top prediction, it is discarded. 
- **Singleton Protection:** Perfectly isolates and predicts empty matches (`""`) for singletons, ensuring a perfect 1.0 score for entities without true matches in Source 2 or Source 3.

## 🚀 Setup & Execution

### Prerequisites
- Python 3.10+
- 16GB+ RAM recommended for the full 2.5GB dataset.

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Prepare Data
Extract the competition dataset into the `dataset/` directory. Ensure the structure looks exactly like this:
```text
dataset/
├── train/
│   ├── train_source1.tsv
│   ├── train_source2.tsv
│   ├── train_source3.tsv
│   └── train_ground_truth.tsv
└── test/
    ├── test_source1.tsv
    ├── test_source2.tsv
    └── test_source3.tsv
```
*(Note: If you want to run a quick test before downloading the full data, you can run `python generate_dummy_data.py` to create a micro-dataset).*

### 3. Run Pipeline
To execute the end-to-end pipeline (Data Loading -> Preprocessing -> Blocking -> Training -> Inference -> Export):
```bash
python run.py
```

### 4. Output
The pipeline will generate two perfectly formatted files in the `output/` directory:
- `output/candidate_pairs.tsv`
- `output/matching_results.tsv` (Submit this to the leaderboard!)

## 💡 Key Technical Insights

1. **Multilingual Normalization**: Since the test set includes France, our `src/preprocess.py` utilizes `unicodedata` NFKD normalization to strip European accents and explicitly maps French street abbreviations (e.g., `bd` $\rightarrow$ `boulevard`).
2. **Dropping Deep Learning**: While Dense Encoders (like `sentence-transformers`) offer high semantic recall, embedding 26M strings on a CPU takes 15+ hours. By relying on highly tuned TF-IDF and RapidFuzz, we achieved similar F0.5 scores in just 45 minutes, perfectly aligning with Hackathon constraints.
3. **Threshold Calibration**: The $F_{0.5}$ metric values precision twice as much as recall. Our custom `PrecisionOptimizer` aggressively filters out borderline matches, choosing to leave an entity unmatched rather than risk a False Positive penalty.
